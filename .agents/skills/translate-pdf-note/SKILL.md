# PDF → перевод → заметка в репозитории

Один скил вместо ручной цепочки: извлечение текста → перевод → полировка → добавление в контент.
Работать по шагам, не пропуская проверки. Сборки (`yarn build`, `yarn dev`) не запускать.

## Шаг 1. Извлечь текст из PDF

Если точный путь не указан, ищи PDF **в первую очередь в `~/Downloads/books`** (включая подпапки, например `~/Downloads/books/PDF`), а уже потом — в `../ai-text/Христианская/translate/archive/` или спрашивай у пользователя.

```sh
pdftotext "/полный/путь/к/файлу.pdf" /tmp/extracted.txt
wc -l -w /tmp/extracted.txt
tail -5 /tmp/extracted.txt
```

Проверь, что текст заканчивается естественно (не обрывается на полуслове). Если оборван — читай чанками или используй `mutool`.
Если `pdftotext` не установлен — Python + PyMuPDF, но не устанавливай пакеты без согласования.

## Шаг 2. Перевести

Обязательно загрузи глобальный скил:

```
skill(name: "spirit-text-translator")
```

Ключевое, что нельзя забыть (детали — в скиле):

- Удалить повторяющиеся служебные блоки: «Multiplying Freedom Ministries», URL, e-mail, навигацию блога, списки «Related Posts».
- **Молитва — не blockquote.** `>` только для стихов Писания. Молитва, занимающая большую часть документа, — обычный текст абзацами.
- Ссылки на Библию — Синодальные сокращения, дефис в нумерованных книгах (`1-Кор. 6:16`). В повествовании — полное название без дефиса.
- **Псалмы:** масоретская нумерация − 1 к Синодальной (`Ps. 16:4` → `Пс. 15:4`, `Ps. 110:1` → `Пс. 109:1`).
- Единое лицо в молитве: если оригинал скачет между I и we — сведи к «я» (или «мы», если молитва соборная), не смешивай в одном абзаце.
- Заголовки: документ — `##`, раздел — `###`, подраздел — `**bold**`. `#` не использовать. Без `---`, без «?» в заголовках, без буквенных маркеров `а) б)`.
- Не переводить обращения молитвы *к* бесам как молитву бесам; тон повелительный, но адресат — Бог.

## Шаг 3. Отполировать

Загрузи глобальный скил и пройди его workflow:

```
skill(name: "spirit-translation-polisher")
```

Минимум, что проверяется:

- Коллокации и кальки («разрывая силу» → «разрывая власть», «к успеху и преуспеванию» → «к успеху и благополучию»).
- Параллелизм списков (все существительные или все глаголы; не мешать «Податель» и «Обеспечивающий»).
- Тавтология («скверна и осквернение», «прежний, который был раньше»).
- Пассив → актив, где звучит канцелярски.
- Согласование числа/рода/лица, форма предлогов (`со`, `во`, `ко`).
- Повторы открывалок абзацев и цепочки родительных падежей.
- Термины единообразны по всему тексту.

Сохрани список правок «было → стало + причина» для финального отчёта.

**После полировки — обновить скилы.** Если в тексте появился новый устойчивый термин освобождения или повторяющаяся калька — добавь 0–6 строк в §1.2 / §6.1 соответствующего глобального скила (`~/.agents/skills/spirit-*/SKILL.md`) и бампни его `CHANGELOG.md`. Одноразовые формулировки и «правила под один случай» не добавляй: 0 строк — нормальный результат.

## Шаг 4. Сверить Писание по MCP

Все библейские цитаты и ссылки сверяй через MCP `bible-ru-synodal` (версия `synodal`):

```
get_passage(reference: "Лев 20:9; Мф 15:4", version: "synodal")
```

Правила вызова:

- Названия книг — без точек: `Мф`, `1Тим`, `1Ин`, `Пс` (не `1-Тим`, не `Мф.`).
- Запятые в стихах не поддерживаются: `Пс 70:8; Пс 70:18` вместо `Пс 70:8,18`.
- Псалмы: масоретская нумерация − 1. Проверяй по содержанию, что стих тот самый (англ. `Ps. 110:1` = `Пс 109:1`).
- MCP отдаёт текст без «ё» — в заметке оставляй «ё» по стилю репозитория.
- Сверяй и blockquote-цитаты, и ссылки в скобках, и пересказы стихов.

⚠️ **Нумерация стихов.** MCP — протестантская редакция Синодалки (РСП), и в отдельных главах она смещена относительно стандартной Синодалки: `Чис 30` (+1), `Нав 6` (−1), `Прит 13` (+1). Поэтому:

- **текст** сверяй по MCP;
- **номер стиха** меняй только если стих не соответствует и в стандартной Синодалке (как `Чис 13:25`, где цитата «возвратились через сорок дней» в Синодалке — ст. 26);
- если MCP показывает другой номер, а по смыслу всё сходится — **не меняй**, это сдвиг редакции.

Если текст расходится — ставь вариант MCP: он нормативный. Если ссылка не соответствует процитированному стиху (например, в оригинале `Rom. 13:1`, а цитируется ст. 7) — исправь ссылку и укажи это в отчёте.

## Шаг 5. Выбрать папку

| Молитвы, освобождение, статьи Multiplying Freedom | `content/notes/multiplying-freedom/` |
| Конспект книги | `content/notes/books/` |

| Уроки освобождения Владимира Михайлова | `content/posts/vladimir-mikhaylov/` |

Если тип неочевиден — задай **один** вопрос, не угадывай.

## Шаг 6. Номер и имя файла

```sh
ls "content/notes/multiplying-freedom/" | sort | tail -5
```

- Номер — максимальный существующий + 1, три цифры (`039-…`).
- Имя: `{NNN}-{Название}.md`, название на русском, без точки в конце.
- **Никакого ВЕРХНЕГО регистра** — ни в имени файла, ни в заголовках, ни в маркерах (`**ШАГ 1.**` → `**Шаг 1.**`).
- `title` — 55–60 символов максимум. Длинное название сокращать: убрать перечисления, имена авторов, эпитеты, кликбейт.

## Шаг 7. Frontmatter

```yaml
---
title: "Название до 60 символов"
description: "Одно предложение о содержании, 20–200 символов."
date: ДД-ММ-ГГГГ
categories: ["статьи", "multiplying-freedom", "молитва"]
featured: false
draft: false
source_url: "https://multiplyingfreedom.com/free-stuff/"
---
```

- `date` — **сегодняшняя** дата из блока System Information (`YYYY-MM-DD` → `ДД-ММ-ГГГГ`). Не копировать из соседних файлов.
- `categories` для `multiplying-freedom`: база `["статьи", "multiplying-freedom"]`; для шагов к свободе добавить `"шаги к свободе"`; для молитв — `"молитва"`.
- `source_url` — только для `multiplying-freedom`.
- Для `books` — `categories: ["книги"]`, без `source_url`, если его нет в оригинале.
- `title` в frontmatter обязан совпадать с первым `##` в теле.

## Шаг 8. Записать файл

Предпочтительно `write_file`. Если контент длинный/кириллический и инструмент капризничает — писать через терминал:

```sh
cat > "content/notes/multiplying-freedom/039-Название.md" <<'EOF'
...
EOF
```

`edit_file` на длинных кириллических строках может падать с `Could not find matching text` — тогда сразу переходи на `sed -i ''` или перезапись файла.

## Шаг 9. Проверки перед отчётом (sweep)

Сначала автоматика:

```sh
python3 scripts/check-note.py "content/notes/multiplying-freedom/NNN-Название.md"
```

Скрипт проверяет frontmatter, `title` ≤ 60 и совпадение с `##`, CAPS, `---`, `?` в заголовках, буквенные маркеры, дефис в нумерованных книгах, служебные блоки, имя файла. Нужно 0 `ERROR`. Дальше — только то, что он не видит:

- [ ] Все `>` — только стихи Писания; молитвы — обычный текст.
- [ ] Ссылки: Синодальные сокращения, дефис в номерах книг, Псалмы в Синодальной нумерации.
- [ ] Цитаты сверены через MCP `bible-ru-synodal` (`synodal`), ссылки соответствуют содержанию стихов.
- [ ] Смысл и термины: быстрый проход по `CHECKLIST.md` скилов translator и polisher.
- [ ] `git --no-optional-locks status --short` показывает только новый файл.

## Шаг 10. Отчёт

Сообщи пользователю:

1. Путь к файлу и номер.
2. `title`, `categories`.
3. Таблицу правок полировки (было → стало → причина).
4. В скилы добавлено: N строк и куда — или «ничего нового».
5. Что пропущено и какой риск остался (одна-две строки).

## Чего не делать

- Не запускать сборки и дев-сервер без явной просьбы.
- Не использовать `npm`/`npx` — только `yarn`.
- Не удалять и не переименовывать исходный PDF и соседние файлы.
- Не менять структуру папок и конфиги.
- Не перезаписывать существующие заметки — только создавать новый номер.
- Не добавлять зависимости.
